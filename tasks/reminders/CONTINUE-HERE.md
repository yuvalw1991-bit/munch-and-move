# תזכורות — חזרות + התניית ההתראה · המשך מכאן

נכתב 3.8.2026 בסוף שיחה שהתקרבה למגבלת ההקשר. **טרם נפרס דבר. הסביבה החיה לא שונתה.**

## מה יובל ביקשה

שני דברים, שאוחדו לפעימה אחת כי הם נוגעים באותם שלושה מקומות:

1. **חזרות אמיתיות.** היום יש רק `times` (שעות קבועות, כל יום) ו-`interval` (כל X דקות בחלון יומי).
   יובל צריכה שבועי, דו-שבועי, חודשי, דו-חודשי ו**חצי-שנתי** — "תזכורת לתרופה יכולה להיות גם חצי שנתית".
2. **התניית ההתראה הנדחפת במצב בפועל** (מפיצ'ר 18) — חלבון שנשאר, מים שפיגרו, אימון שלא נרשם.
   כרגע כל תזכורת נשלחת עם גוף קבוע: `"תזכורת מ-Munch & Move"`.

### החלטות שכבר התקבלו (מיובל, במפורש)
- **בורר מפורש** בתזכורת ("קשור ל-": מים / חלבון / אימון / ללא) — **ולא** ניחוש לפי אמוג'י,
  כי "💧 לקחת ויטמין D" היה מזוהה בטעות כמים ומושתק ביום שבו שתתה מספיק.
- **לפרוס כשמוכן** — לא צריך אישור נוסף לפני הפריסה, אבל הפריסה נוגעת במשתמשים אמיתיים.
- הכול אדיטיבי: תזכורת שקיימת היום חייבת להמשיך לפעול **בדיוק** אותו דבר.

## מה כבר נעשה ✅

### המתזמן — גמור ומוכח
`scheduler.cjs` + `scheduler.test.cjs` כאן בתיקייה (סיומת `.cjs` כי `package.json`
של הפרויקט מגדיר `"type": "module"`). **37 בדיקות עוברות**, כולל
**13,440 השוואות מול המתזמן החי — אפס הבדלים**, כלומר תאימות לאחור מוכחת ולא מונחת.

מכוסה: יומי · כל N ימים · שבועי עם ימי שבוע · דו-שבועי · חודשי · הצמדת ה-31 לחודש קצר ·
דו-חודשי · חצי-שנתי · שנתי · אינטרוול שמכבד את החזרה · קלט פגום · אזורי זמן שונים ·
365 ימי "עכשיו" בלי שאף פעם יוחזר מועד בעבר.

```bash
node tasks/reminders/scheduler.test.cjs
```

**החלטה שנלקחה תוך כדי:** בהתחלה שיניתי את `interval` לירות על רשת קבועה (08:00, 10:00…)
במקום "עכשיו + אינטרוול". יציב יותר — אבל זה **משנה בשקט את זמני הירי של תזכורות קיימות**,
ויובל לא ביקשה. הוחזר להתנהגות הקיימת, עם הערה בקוד.

### הסכמה — הסקריפט מוכן, **טרם הורץ**
`migrate.mjs` — אדיטיבי בלבד, קורא את הטוקן מ-`SUPABASE_ACCESS_TOKEN`.

```bash
node tasks/reminders/migrate.mjs --inspect   # לראות את הסכמה הנוכחית
node tasks/reminders/migrate.mjs --apply     # להריץ (טרם הורץ!)
```

עמודות: `repeat_unit` ('day'|'week'|'month', ברירת מחדל 'day') · `repeat_n` (ברירת מחדל 1) ·
`weekdays` int[] · `month_day` · `anchor_day` date · `goal` ('water'|'protein'|'workout'|null).
ברירות המחדל = ההתנהגות הקיימת בדיוק. יש גם backfill של `anchor_day` מ-`created_at`.

## מה נשאר ⬜

1. **להריץ את המיגרציה** (`--apply`).
2. **מסך התזכורות ב-`index.html`** (בערך שורה 9693 ואילך, `// ---------- Push reminders`):
   - להחליף את `remNextFire()` בלוגיקה מ-`scheduler.js`
   - בורר חזרה (יחידה + כל N + ימי שבוע + יום בחודש)
   - בורר "קשור ל-"
   - `remDescribe()` צריך לתאר גם את החזרה
   - השדות החדשים ב-INSERT (בערך שורה 9823)
3. **פונקציית ה-Edge** — להוריד מחדש, לעדכן `nextFire()` באותה לוגיקה, ולהוסיף את ההתניה.
4. **סוכן QA ייעודי** (חובה לפי CLAUDE.md), ואז פריסה.

## מלכודות — לקרוא לפני שנוגעים

- ⚠️ **מקור ה-Edge Function מכיל את מפתח ה-VAPID הפרטי ואת סוד ה-cron בקוד.**
  **אסור לשמור אותו בתיקיית הפרויקט** — `.vercelignore` לא מכסה `supabase/`, וזה היה
  מפרסם אותם לאינטרנט. לעבוד עליו בסקרצ'פאד בלבד.
  לשחזור: `npx supabase@2.111.0 functions download push-reminders --project-ref suifyxxjvritdqthbivm`
  (עובד — כך הושג המקור. ההנחה ש"המקור אבוד" הייתה שגויה.)
- ⚠️ **לא לרוטט את מפתח ה-VAPID.** רוטציה מבטלת בשקט כל מנוי פוש קיים.
  אם מעבירים את הסודות ל-Supabase secrets — להעביר את **אותו** ערך.
- ⚠️ **המתזמן חי בשני עותקים** — `remNextFire()` בלקוח ו-`nextFire()` ב-Edge. שינוי חייב
  להיכנס לשניהם, אחרת תזכורת תופיע בזמן שונה מזה שהאפליקציה הבטיחה ביצירה.
- ⚠️ **ההערה בראש ה-Edge Function אומרת "every 5 minutes" — היא כנראה לא מעודכנת.**
  לפי הזיכרון, יובל בחרה `0,30 * * * *` (כל חצי שעה) כדי להקטין עומס. **לאמת מול pg_cron**
  לפני שמסתמכים על הגרנולריות.
- ⚠️ **הוק בטיחות חוסם `curl`/פקודה מוטבעת עם `SUPABASE_ACCESS_TOKEN`.** לשים קוד כזה
  בקובץ `.mjs` ולהריץ עם node — כפי ש-`migrate.mjs` עושה.
